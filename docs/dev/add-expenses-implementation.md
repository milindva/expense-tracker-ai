# Add Expenses Feature — Developer Documentation

## Overview

The Add Expenses feature lets users record new expenses and edit existing ones through a modal form. It is front-end only — all state is managed in React and persisted to `localStorage`. No server round-trip is involved. The same `ExpenseForm` component handles both add and edit modes, toggled by the presence of the `editingExpense` prop.

## Interfaces

### `ExpenseFormProps`

```ts
interface ExpenseFormProps {
  isOpen: boolean                               // controls visibility; unmounts when false
  onClose: () => void                           // called after successful save or cancel
  onSave: (data: Omit<Expense, 'id' | 'createdAt'>) => void  // receives validated payload
  editingExpense?: Expense | null               // omit or null for add mode; provide for edit
}
```

### Internal `FormData`

```ts
interface FormData {
  date: string        // ISO date string YYYY-MM-DD
  amount: string      // raw string from input — parsed to float only at submit
  category: Category  // one of the six Category values
  description: string
}
```

### Internal `FormErrors`

```ts
interface FormErrors {
  date?: string        // non-empty string = error message to display
  amount?: string
  description?: string
}
```

### `Expense` (from `lib/types.ts`)

```ts
export interface Expense {
  id: string        // generated by generateId()
  date: string      // ISO date YYYY-MM-DD
  amount: number    // parsed float, 2 decimal places
  category: Category
  description: string
  createdAt: string // full ISO timestamp set at creation, never mutated on edit
}

export type Category = 'Food' | 'Transportation' | 'Entertainment' | 'Shopping' | 'Bills' | 'Other'
```

## Logic

### Add vs. Edit mode

The form operates in one of two modes depending on the `editingExpense` prop:

| Prop value | Mode | Title | Submit button |
|---|---|---|---|
| `null` / `undefined` | Add | "Add Expense" | "Add Expense" |
| `Expense` object | Edit | "Edit Expense" | "Save Changes" |

A `useEffect` keyed on `[editingExpense, isOpen]` populates the form when entering edit mode, or resets it to defaults when opening in add mode.

### Field defaults (add mode)

| Field | Default |
|---|---|
| Date | Today (`new Date().toISOString().split('T')[0]`) |
| Amount | `''` (empty) |
| Category | `'Food'` |
| Description | `''` (empty) |

### Amount sanitization — `handleAmountChange`

Amount is kept as a string in state to give the user a natural typing experience. On each keystroke:

```ts
const cleaned = value.replace(/[^0-9.]/g, '').replace(/(\..*)\./g, '$1')
```

1. Strips all non-numeric, non-period characters (letters, currency symbols, etc.)
2. Prevents more than one decimal point

Parsing to a float happens only at submit time.

### Validation — `validate()`

All fields are validated synchronously before submission. Errors are set via `setErrors` and displayed inline below each field.

| Field | Rules |
|---|---|
| `date` | Must be non-empty |
| `amount` | Must be non-empty, parse to a finite number, and be > 0; must be ≤ 1,000,000 |
| `description` | Must be non-empty (after `.trim()`); must be ≤ 200 characters |

Category is not validated — a default is always selected.

### Submit flow — `handleSubmit`

```
handleSubmit()
  → e.preventDefault()
  → validate() — abort if invalid
  → setIsSubmitting(true)
  → await setTimeout(200ms)       ← synthetic delay for perceived smoothness
  → onSave({
      date, category,
      amount: parseFloat(parseFloat(form.amount).toFixed(2)),  ← round to 2dp
      description: form.description.trim()
    })
  → setIsSubmitting(false)
  → onClose()
```

The double `parseFloat` / `toFixed(2)` pattern ensures the stored amount is always a 2-decimal-place float (e.g., `12.5` → `12.50`) without storing a string.

### `useExpenses.addExpense`

```ts
const addExpense = useCallback((data: Omit<Expense, 'id' | 'createdAt'>) => {
  const newExpense: Expense = {
    ...data,
    id: generateId(),
    createdAt: new Date().toISOString(),
  }
  setExpenses((prev) => [newExpense, ...prev].sort((a, b) => b.date.localeCompare(a.date)))
}, [])
```

- Generates a `id` via `generateId()` (timestamp base-36 + random suffix — not a UUID)
- Sets `createdAt` to the current timestamp
- Prepends the new expense to the array, then re-sorts by date descending using lexicographic comparison (correct for ISO `YYYY-MM-DD` strings)

### `useExpenses.updateExpense`

```ts
const updateExpense = useCallback((id: string, data: Omit<Expense, 'id' | 'createdAt'>) => {
  setExpenses((prev) =>
    prev.map((e) => (e.id === id ? { ...e, ...data } : e))
       .sort((a, b) => b.date.localeCompare(a.date))
  )
}, [])
```

Merges the new field values over the existing expense (preserving `id` and `createdAt`), then re-sorts.

### localStorage persistence

A `useEffect` in `useExpenses` fires whenever `expenses` changes (after initial load):

```ts
useEffect(() => {
  if (isLoaded) saveExpenses(expenses)
}, [expenses, isLoaded])
```

`saveExpenses` wraps `localStorage.setItem` in a `try/catch` — write failures are silently swallowed. `loadExpenses` seeds 20 sample expenses if the key is absent.

Both functions guard against server-side rendering with `if (typeof window === 'undefined') return`.

## Integration in `app/page.tsx` and `app/expenses/page.tsx`

`ExpenseForm` is mounted in both pages. The owning page keeps the `isFormOpen` and `editingExpense` state:

```tsx
const [isFormOpen, setIsFormOpen] = useState(false)
const [editingExpense, setEditingExpense] = useState<Expense | null>(null)

// Open for add
<Navigation onAddExpense={() => setIsFormOpen(true)} />

// Open for edit
function handleEdit(expense: Expense) {
  setEditingExpense(expense)
  setIsFormOpen(true)
}

// Reset on close
function handleFormClose() {
  setIsFormOpen(false)
  setEditingExpense(null)
}

// Delegate to useExpenses
function handleSave(data: Omit<Expense, 'id' | 'createdAt'>) {
  if (editingExpense) {
    updateExpense(editingExpense.id, data)
  } else {
    addExpense(data)
  }
}

<ExpenseForm
  isOpen={isFormOpen}
  onClose={handleFormClose}
  onSave={handleSave}
  editingExpense={editingExpense}
/>
```

Success feedback (toast notification) is wired in the owning page — `ExpenseForm` itself emits none.

## Modal shell — `components/ui/Modal.tsx`

`ExpenseForm` renders inside the shared `Modal` component (size `'md'`, `max-w-lg`). The modal:

- Returns `null` when `isOpen` is `false` — unmounting resets all `ExpenseForm` local state automatically
- Attaches a document-level `keydown` listener to close on `Escape`
- Sets `document.body.style.overflow = 'hidden'` to prevent background scroll
- Closes when the user clicks the dark backdrop

## Limitations and Constraints

| Constraint | Location | Detail |
|---|---|---|
| Maximum amount | `ExpenseForm.validate` | Hard-coded at $1,000,000 |
| Maximum description length | `ExpenseForm.validate` | Hard-coded at 200 characters |
| Future dates blocked | `<input type="date" max={today}>` | Browser-enforced only; not re-validated on the server |
| localStorage quota | `lib/storage.saveExpenses` | Write failures are silently swallowed; user receives no feedback |
| Float precision | `handleSubmit` | Amounts stored as JavaScript floats; extreme values (e.g., repeating decimals) may have sub-cent drift |
| Category list is fixed | `lib/utils.ts` | `CATEGORIES` is a hardcoded array; users cannot create custom categories |
| ID collisions | `lib/utils.generateId` | Extremely unlikely but `Date.now() + random` is not a UUID; could theoretically collide under rapid programmatic inserts |
| Synthetic 200ms delay | `handleSubmit` | Not tied to any real async operation |

## Maintainability

### Adding a new category

1. Add the value to the `Category` union in `lib/types.ts`
2. Add entries for the new value in `CATEGORIES`, `CATEGORY_COLORS`, `CATEGORY_STYLES`, and `CATEGORY_ICONS` in `lib/utils.ts`

No changes to `ExpenseForm` are needed — the category grid iterates `CATEGORIES` dynamically.

### Adding a new form field

1. Add the field to the `Expense` interface in `lib/types.ts`
2. Add it to `FormData` in `ExpenseForm.tsx`
3. Add a validation rule in `validate()`
4. Wire the field in `handleSubmit`'s `onSave` call
5. Add UI markup in the form body

### Testing

`ExpenseForm` requires a React testing environment (React Testing Library). Key cases:

- Pre-filled fields when `editingExpense` is provided
- Validation errors appear for each invalid field and clear on re-submit
- Amount sanitization strips letters and prevents multiple decimal points
- Submit is disabled while `isSubmitting` is true
- `onSave` is called with a correctly-shaped payload (amount as float, description trimmed)
- `onClose` is called after a successful save

`useExpenses` hooks (`addExpense`, `updateExpense`) can be tested in isolation by mocking `localStorage` and asserting the resulting `expenses` array is sorted descending by date.
